# Xの手動投稿

オリパーク、満満、東京満満で共通の操作です。店頭・郵送ごとに複数のXアカウントを登録できます。投稿先は毎回明示的に選択します。

## 操作

1. HarakaにGoogleログインし、「X投稿」→「アカウント管理」で、用途を選んでXを認証します。表示名は「店頭買取」「郵送買取」などに変更できます。
2. 「X投稿」で店頭／郵送、作成日、投稿先を選び、生成済みの買取表画像を選択します。選択した順序を変更できます。
3. 下書きを保存します。画像はこの時点で別の保存先にコピーされ、元の買取表を再生成しても変わりません。4枚ずつの投稿に分かれます。
4. 各投稿の画像と本文を確認・修正し、変更を保存します。投稿先を含む最終確認にチェックして「投稿する」を押します。
5. 画面を開いたまま完了を待ちます。各投稿の結果とXへのリンクが保存されます。途中停止後は未投稿分から再開できます。

投稿ボタン以外ではXに投稿しません。タブを閉じると、その時点で処理中の1件の後で停止します。履歴から再開してください。予約投稿・バックグラウンドでの継続送信は今回の対象外です。

## 初回に利用者が行う設定・認証

### X Developer Console

- 利用するXアプリでOAuth 2.0のUser authenticationを有効にし、機密クライアント（Web App／Automated App or Bot）としてClient ID・Client Secretを取得します。
- 投稿・画像投稿ができる権限にします。アプリが要求するスコープは `tweet.read tweet.write users.read offline.access media.write` です。
- 利用する環境のコールバックURLを、下表のとおり完全一致で登録します。同じXアプリを使う場合は、各URLを登録します。
- X APIの利用枠・クレジットと支出上限を確認してください。購入や課金設定は利用者側で行います。
- Client Secretをチャットに貼らず、API側のSecret Managerに登録してください。設定先は次節に記載しています。

| 環境 | Xに登録するコールバックURL | APIサービス / STORE_NAME |
| --- | --- | --- |
| オリパーク | `https://harakawebapp-web.vercel.app/api/posting/x/oauth/callback` | `haraka-api` / `oripark` |
| 満満 | `https://harakafor-manman-web.vercel.app/api/posting/x/oauth/callback` | `haraka-manman-api` / `manman` |
| 東京満満 | `https://haraka-for-manman-tokyo-web.vercel.app/api/posting/x/oauth/callback` | `haraka-manman-akihabara-api` / `manman-akihabara` |

設定・リリース後、各Harakaの「アカウント管理」で、店頭用・郵送用のXアカウントをそれぞれ認証します。Xの認可画面で表示中のアカウントを確認してください。再認証では元のXユーザーIDと一致しないアカウントを受け付けません。1つのアカウントには1つの用途を割り当てます。同じ用途に複数アカウントを登録できます。

## 管理者側の設定

GCPプロジェクトは `spectre-tomstocks-20260227`、リージョンは `asia-northeast1`。APIサービスごとに以下を設定します。

| 設定 | 内容 |
| --- | --- |
| `X_CLIENT_ID` | XのOAuth 2.0 Client ID |
| `X_CLIENT_SECRET` | XのOAuth 2.0 Client Secret。Secret Manager参照を使用 |
| `X_OAUTH_CALLBACK_URL` | 上表の、そのAPIに対応するフロントエンドURL |
| `X_TOKEN_ENCRYPTION_KEY` | 暗号学的乱数32バイトをBase64化した値。Secret Managerで保管。既存トークンを復号するため、再デプロイ時も維持 |
| `ORDER_LIST_IMPORT_API_TOKEN` | 既存のAPI内部認証キー。32文字以上。対応するVercel側と一致させる |
| `STORE_NAME` | 上表の店舗識別子。別店舗の値を流用しない |

Vercel側は既存のGoogle運用者ログイン、運用者メール許可設定、APIの接続先を使います。投稿機能は `OPERATOR_AUTH_REQUIRED=false` の場合も運用者ログインが必須です。Googleログインのクライアント設定が未設定なら、既存のログイン設定も必要です。Xの秘密情報を `NEXT_PUBLIC_*` に設定しないでください。

2026-11-18の読み取り確認では、3つのAPIとも `X_*` の設定がありませんでした。オリパークの既存登録1件は期限切れ、満満・東京満満の登録は0件でした。このため、新方式でのX認証と実投稿の確認は未実施です。

## リリース手順

1. 対象ブランチのレビューと本番リリースの承認を得ます。現在稼働するリビジョン・イメージ・設定を記録します。
2. 共有Supabase `abyecthqjjssegwazhwm` について、`x_credential` の `(store, x_user_id)` に重複がないことを確認します。マイグレーション `20261118072951_x_manual_posting.sql` を一度だけ適用します。両リポジトリに同一のファイルがあります。無関係な未適用マイグレーションをまとめて実行しないでください。
3. APIの設定を登録してAPIをデプロイし、対応するWebをデプロイします。オリパークでは、11月18日の稼働リビジョン `haraka-api-cbfix-20261118` の独自買取表修正が別の作業コピーに残っているため、その修正を含めたリリース元の統合確認が必要です。この機能ブランチだけで稼働版を上書きしないでください。
4. 未ログインの投稿APIが401になること、ログイン後の設定・画像一覧・下書き保存・読み戻しが成功すること、各APIの店舗が一致することを確認します。
5. 各Xアカウントの所有者が認証します。「接続を確認」でユーザーIDと接続を確認します。
6. 利用者が承認した本文・画像・投稿先で、各用途の初回投稿を行います。X上の画像・本文・アカウント・返信順と、Harakaに保存された投稿IDを照合して本番確認を完了します。

マイグレーションは既存の履歴を削除しません。旧方式の送信ルートは登録せず、投稿は認証済みの新ルートに統一しています。旧下書きがある場合は新画面で作り直します。

### 障害時

- Xから結果を受信できない場合は「結果を要確認」で停止します。自動再送しません。X上で確認し、該当投稿のURLを登録するか、「投稿されていない」と確認してから再開します。URLのアカウント・本文・画像枚数・返信先を照合します。画像そのものの一致は目視でも確認してください。
- 処理中のままの場合は、5分の実行期限後に「中断した処理を確認する」を使います。送信前なら再開可能、送信開始後なら上記の結果確認が必要です。
- 429などの制限は、その投稿で停止します。制限解除後に手動で再開します。投稿済みの内容は再送しません。
- ロールバック時はまず投稿への操作を停止し、処理中の結果を確認します。DBの追加列・保存画像・投稿ID・暗号化キーは残します。旧APIは新しい暗号化トークンと認証方式に対応しないため、X設定を無効化したうえで戻すか、投稿機能の修正版を前進適用します。
- 下書きのDB保存結果が不明な場合は、画像の誤削除を避けてコピーを保持します。不要な画像を後で整理する場合も、すべての保存済み下書きから参照されていないことを確認してから行います。

## 現在の範囲と検証

- 生成済み買取表画像を最大200枚、1投稿4枚まで。PNG・JPEG・WebPは各5MB以下。通常投稿の重み付き280文字上限（日本語は約140字）。本文テンプレートの適用と未入力変数の検出に対応しています。
- 店舗・用途・XユーザーIDによる照合、同時送信の排他、古いタブの更新拒否、投稿済み本文の変更禁止、通信断後の結果確認、画像の固定を実装しています。
- 実際のマイグレーションをPostgres互換のPGliteで実行し、HTTP経由の下書き作成から結果保存まで、複数送信・障害・権限のケースをテストしています。Webのセッション・CSRF・OAuth state検証もテストしています。
- ローカルの本番ビルドをブラウザーで操作し、店頭／郵送切替、画像6枚の2投稿への分割、本文保存、最終確認、結果表示、スマートフォン表示を模擬APIで確認しています。実際のXへの送信はしていません。

公式資料: [OAuth 2.0](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code)、[画像アップロード](https://docs.x.com/x-api/media/upload-media)、[投稿API](https://docs.x.com/x-api/posts/create-post)、[X API料金](https://docs.x.com/x-api/getting-started/pricing)。
